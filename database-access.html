    7. Database Access

    The TypeScript course devotes three chapters to accessing a MySQL database: the native driver [mysql2], followed by two ORM ([TypeORM] and [Prisma]), using the same example—two databases, [dbpersonnes] (a single table) and [dbecole] (four related tables: classes, students, subjects, and grades). This chapter is identical to the first one, then combines the two chapters ORM into a single one: Dart has no mature equivalent of [TypeORM] or [Prisma] for MySQL (see the sidebar at the end of the chapter), and rather than forcing an artificial correspondence with either one, we construct a “lightweight ORM” that demonstrates what a ORM actually does, by writing it ourselves.

    7.1. Direct access to the database

    The TypeScript [mysql2] package has no equivalent maintained by the MySQL team itself on the Dart side. An early version of this chapter used [package:mysql1] (pub.dev/packages/mysql1), a widely used pure Dart driver—MySQL—but it turned out to be incompatible with MySQL 8.4 (the version shipped with Laragon): even a query as simple as “select 1” consistently failed with the protocol error “Got packets out of order,” a known and unresolved bug in the package (issues GitHub adamlofts/mysql1_dart #112 and #161). We are therefore now using [package:mysql_client_plus] (pub.dev/packages/mysql_client_plus), an actively maintained fork that has been tested with MySQL and 8.x, including API — [MySQLConnection.createConnection], [connexion.connect], [connexion.execute], [connexion.close] — remains very similar to that of [mysql2].

    7.1.1. Preparing the [dbpersonnes] database

    The dbpersonnes database contains only one table, personnes, which uses the same schema as the one used in the Python course (columns id, first\_name, last\_name, age, with a uniqueness constraint on the pair (last\_name, first\_name)). The script sql/create_dbpersonnes.sql below creates the database, the application user, and the table, then inserts five arbitrary people into it:

-- Recrée la base [dbpersonnes] utilisée par le chapitre « Accès à MySQL avec le
-- pilote natif [mysql2] », avec des données arbitraires (les originales du cours
-- Python/Flask 2020 n'étant plus disponibles).
--
-- Utilisation :
-- mysql -u root -p < create_dbpersonnes.sql
--
-- Crée la base, l'utilisateur applicatif [admpersonnes/nobody] (mêmes
-- identifiants que le cours d'origine) et la table [personnes].

CREATE DATABASE dbpersonnes CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

CREATE USER IF NOT EXISTS 'admpersonnes'@'localhost' IDENTIFIED BY 'nobody';
GRANT ALL PRIVILEGES ON dbpersonnes.* TO 'admpersonnes'@'localhost';
FLUSH PRIVILEGES;

  id INT PRIMARY KEY,
  prenom VARCHAR(30) NOT NULL,
  nom VARCHAR(30) NOT NULL,

// Database: databases/mysql/mysql-01.ts.
//
// First step: log in to the database MySQL [dbpersonnes], then
// log out.
//
// [choix technique] The TypeScript [mysql2] package has no direct equivalent
// Dart-side direct version maintained by the MySQL team itself. An early
// version of this chapter used [package:mysql1] (pub.dev/packages/
// mysql1), a widely used pure Dart driver—but one that
// proved to be incompatible with MySQL 8.4 (included with Laragon): even a query
// as trivial as "select 1" would consistently fail with the
// protocol error “Got packets out of order” (a known, unresolved bug in the
// packet). Therefore, we use [package:mysql_client_plus]
// (pub.dev/packages/mysql_client_plus), an actively maintained fork, and
// tested with MySQL 8.x, including API - [MySQLConnection.createConnection],
// [connexion.connect], [connexion.execute], [connexion.close] - remains very
// close to that of [mysql2].
import 'package:mysql_client_plus/mysql_client_plus.dart';

// connection to the database MySQL [dbpersonnes]
// the user's identity is (admpersonnes, nobody)
const String user = 'admpersonnes';
const String pwd = 'nobody';
const String host = 'localhost';
const int port = 3306;
const String database = 'dbpersonnes';

Future<void> main() async {
  // [différence avec TypeScript] no union type "MySqlConnection |
  // "undefined" here: a nullable field ([MySQLConnection?]) plays the same
  // role—"not yet logged in" is represented by [null], exactly
  // as “not yet logged in” was represented by [undefined] on the TS side.
  MySQLConnection? connexion;
  try {
    print('Connexion au SGBD MySQL en cours...');
    // [différence avec TypeScript] unlike mysql1 (and mysql2),
    // [mysql_client_plus] separates the CRÉATION from the connection object
    // ([createConnection], which does not yet involve any network traffic) from
    // the actual establishment of the connection ([connect], which negotiates the
    // protocol with the server)—two distinct stages, whereas
    // mysql1 conflated them into a single call [MySqlConnection.connect].
    // [connexion] (the nullable variable from the [finally] block) is not assigned
    // only after [connect] succeeds: if [connect] fails, [connexion]
    // remains [null], and [finally] will not attempt to close a connection
    // that was never actually opened.
    final nouvelleConnexion = await MySQLConnection.createConnection(
      host: host,
      port: port,
      userName: user,
      password: pwd,
      databaseName: database,
    );
    await nouvelleConnexion.connect();
    connexion = nouvelleConnexion;
    // followed by
    print(
      "Connexion MySQL réussie à la base database=$database, host=$host sous l'identité user=$user, passwd=$pwd",
    );
  } catch (erreur) {
    // displays the error
    print("L'erreur suivante s'est produite : $erreur");
  } finally {
    // the connection is closed if it was opened
    if (connexion != null) {
      await connexion.close();
    }
  }
}

    • line 19: [import 'package:mysql_client_plus/mysql_client_plus.dart';]: the new MySQL driver written entirely in Dart, replacing [package:mysql1]—which is incompatible with MySQL 8.4 (included with Laragon): even a query as trivial as “select 1” would consistently fail with the protocol error “Got packets out of order,” a known and unresolved bug in the package (see the comment at the top of the file).
    • Line 34: [MySQLConnection? connexion;]: a NULLABLE field serves exactly the same purpose as the union type [MySqlConnection | undefined] of TypeScript - [null] represents “not yet connected,” just like [undefined] relative to TS.
    • Lines 47–55: [final nouvelleConnexion = await MySQLConnection.createConnection(...); await nouvelleConnexion.connect(); connexion = nouvelleConnexion;]: [mysql_client_plus] separates CRÉATION from the connection object ([createConnection], which is not yet exchanging any network traffic) to the actual establishment of the connection ([connect], which negotiates the protocol with the server)—two distinct stages, whereas [mysql1] (like [mysql2] on the TypeScript side) combined them into a single call. [connexion] (the nullable variable from [finally]) is assigned only after [connect] succeeds, so that [finally] never closes a connection that was never actually opened.
    • [try] / [catch] / [finally]: structure identical to the previous version—the connection is always closed in [finally], regardless of whether an error occurred.

// connects to and then disconnects from (login, password) the database [database] on the server
// [hote]; throws an exception if there is a problem
Future<void> connexion(String hote, int port, String database, String login, String pwd) async {
  MySQLConnection? cnx;
  try {
    // connection—[createConnection] creates the object; [connect] actually negotiates
    // actually negotiates with the server (see comment on mysql_01.dart); we
    // only affects [cnx] after a successful [connect], so that [finally]
    // never closes a connection that failed
    final nouvelleConnexion = await MySQLConnection.createConnection(
      host: hote,
      port: port,
      userName: login,
      password: pwd,
      databaseName: database,
    );
    await nouvelleConnexion.connect();
    cnx = nouvelleConnexion;
    print(
      "Connexion réussie à la base database=$database, host=$hote sous l'identité user=$login, passwd=$pwd",
    );
  } finally {
    // the connection is closed if it has been opened
    if (cnx != null) {
      await cnx.close();
      print('Déconnexion réussie\n');
    }
  }
}

// connection credentials

    print('$erreur');

}

    • Lines 10–36: [Future<void> connexion(String hote, int port, String database, String login, String pwd) async { ... }]: The connection is encapsulated in a reusable function, which throws an exception in case of failure rather than catching it itself—it’s up to the caller to decide what to do with it.     • [main] calls this function twice, in two separate blocks, [try] and [catch]: once with valid identifiers and once with invalid identifiers, to illustrate both paths.

import 'package:mysql_client_plus/mysql_client_plus.dart';

// executes an update query on the connection
Future<void> executeSql(MySQLConnection connexion, String requete) async {
  await connexion.execute(requete);

// ---------------------------------------------- main
// connection credentials
const String id = 'admpersonnes';
const String pwd = 'nobody';
const String host = 'localhost';
const int port = 3306;
const String database = 'dbpersonnes';

Future<void> main() async {
  // Let’s take it step by step
  late final MySQLConnection connexion;
  try {
    // connection - [package:mysql_client_plus], like mysql1 before it,
    // executes each query in its own transaction by default
    // auto-commit (equivalent to AUTOCOMMIT=True on the Python side)
    connexion = await MySQLConnection.createConnection(
      host: host,
      port: port,
      userName: id,
      password: pwd,
      databaseName: database,

    print("L'erreur suivante s'est produite : $erreur");

    // (dart:io) - same semantics, same process exit code
    exit(1);

  // if it does not exist, an error will occur—this is ignored
  try {
    await executeSql(connexion, 'drop table personnes');
  } catch (_) {
    // ignored—[_] indicates that the exception value is ignored
  }

  // Create the "people" table
  const requete = 'create table personnes (id int PRIMARY KEY, prenom varchar(30) NOT NULL, nom varchar(30) NOT NULL, '
      'age integer NOT NULL, unique(nom,prenom))';
  try {
    await executeSql(connexion, requete);
    print('$requete : requête réussie');
  } catch (erreur) {
    print("L'erreur suivante s'est produite : $erreur");
  } finally {
    await connexion.close();
  }
}

    • Lines 10–12: [Future<void> executeSql(MySQLConnection connexion, String requete) async { await connexion.execute(requete); }]: a utility function to execute a SQL update command (here, a DROP TABLE followed by a CREATE TABLE) - [connexion.execute(...)] replaces [connexion.query(...)] from [mysql1] (same role, new method name on the [mysql_client_plus] side).

    • Line 47: [try { await executeSql(connexion, 'drop table personnes'); } catch (_) {}]: The fact that [_] is passed as a parameter to [catch] indicates that the exception value is being ignored—the table may simply not exist yet.

    // mysql_module.dart
// databases/mysql/mysql-module.ts directory: reusable functions for
// executing a list (or file) of SQL commands on an open connection
// MySQL.
//
// [migration] This file originally used [package:mysql1], which was
// proved to be incompatible with MySQL 8.4 (see comment by pubspec.yaml). It was
// been ported to [package:mysql_client_plus]—see below for the difference
// that this changes how transactions are handled.
import 'dart:io';
import 'package:mysql_client_plus/mysql_client_plus.dart';

// displays the result of a SQL command (result of an execute() of
// mysql_client_plus)
// - if [resultats.cols] is not empty, it was a SELECT: display the
// columns and then the rows;
// - otherwise, it was an update command (INSERT/UPDATE/DELETE/DDL):
// displays the number of modified rows ([resultats.affectedRows],
// equivalent to the [rowcount] for a cursor).
void _afficherInfos(IResultSet resultats) {
  if (resultats.cols.isNotEmpty) {
    // this was a SELECT - [cols] describes the requested columns
    final titres = resultats.cols.map((c) => c.name).toList();
    final entete = titres.join(', ');
    print(entete);
    print('*' * entete.length);
    for (final ligne in resultats.rows) {
      print(titres.map((t) => ligne.colByName(t)).toList());
    }
    print('*' * entete.length);
  } else {
    // no columns described—update order
    print('nombre de lignes modifiées : ${resultats.affectedRows}');
  }
}

// uses the open connection [connexion]
// executes the SQL commands contained in the list on this connection
// [commandesSql] (one command per element; empty lines or
// lines starting with # are ignored)
// - if follow=true, each execution of a SQL command is followed by a
// message indicating whether it succeeded or failed;
// - if stop=true, the function stops at the first error encountered,
// otherwise, it executes all commands;
// - if avecTransaction=true, any error cancels all previously executed SQL
// that were previously executed (rollback); otherwise, each command is validated
// independently (default behavior of MySQL, in AUTOCOMMIT);
// the function returns a list [erreur1, erreur2, ...]
//
// [différence avec TypeScript] mysql2 exposes directly
// `connexion.beginTransaction()/commit()/rollback()`. [package:mysql1]
// (used in an earlier version of this file) did not expose these
// methods one by one: the transaction had to be controlled “manually” by
// sending the commands SQL, [START TRANSACTION], [COMMIT], and
// [ROLLBACK]. [package:mysql_client_plus] finally provides the direct equivalent
// of mysql2: `connexion.transactional<T>((cnx) async { ... })` executes the
// callback within a transaction, automatically commits (COMMIT) if it
// completes normally, and automatically rolls back (ROLLBACK) if it throws a
// exception—no further SQL transaction control commands to write
// ourselves.
Future<List<String>> executeListOfCommands(
  MySQLConnection connexion,
  List<String> commandesSql, {
  bool suivi = false,
  bool arret = true,
  bool avecTransaction = true,
}) async {
  final erreurs = <String>[];

  //actually executes the commands on the provided connection [cnx]: this is
  // either [connexion] itself (no transaction) or the
  // "working" connection that [transactional] provides to its callback (with
  // transaction)—the loop is written only once for both cases
  Future<void> executerCommandes(MySQLConnection cnx) async {
    for (final commandeBrute in commandesSql) {
      // we remove the leading and trailing whitespace from the current command
      final commande = commandeBrute.trim();
      // Is the command empty or a comment? Move on to the next one
      if (commande == '' || commande[0] == '#') {
        continue;
      }
      // execute the current command
      try {
        final resultats = await cnx.execute(commande);
        // No error
        if (suivi) {
          print('[$commande] : Exécution réussie');
        }
        _afficherInfos(resultats);
      } catch (erreur) {
        final msg = '$commande : Erreur ($erreur)';
        erreurs.add(msg);
        if (suivi) {
          print(msg);
        }
        // Stop?
        if (avecTransaction || arret) {
          // With transaction: Re-trigger the error so that
          // [connexion.transactional] triggers ROLLBACK - with
          // [package:mysql_client_plus], it is EXCEPTION that controls
          // the cancellation, not just a loop termination as with the
          // ROLLBACK manual for the mysql1 version
          if (avecTransaction) rethrow;
          return;
        }
      }
    }
  }

  if (avecTransaction) {
    try {
      await connexion.transactional((cnx) => executerCommandes(cnx));
    } catch (_) {
      // the error has already been logged in [erreurs] above; it
      // suppress it here to return the list of errors normally to
      // the caller, exactly as the mysql1 version did (which
      // never allowed exceptions to escape from this function)
    }
  } else {
    await executerCommandes(connexion);
  }
  return erreurs;
}

    7.1.9. Conclusion

    The port of the native driver is faithful to the original TypeScript. After an initial attempt with [package:mysql1]—which was abandoned due to incompatibility with MySQL 8.4— [package:mysql_client_plus] ultimately provides a API that is even closer to [mysql2] than [mysql1] was: [connexion.transactional(...)] is the direct equivalent of [beginTransaction()]/[commit()]/[rollback()], whereas [mysql1] would have required manually managing the transaction using the commands SQL, [START TRANSACTION], [COMMIT], and [ROLLBACK]. One difference remains, albeit a more subtle one: the columns DECIMAL ([matieres.coefficient], [notes.valeur] in the [dbecole] database) require an explicit conversion using a small helper [_decimal] ([typedColByName<String>(...)] then [num.parse(...)]), since direct conversion to [num] or [double] is not supported by the driver for this SQL type.

    7.2. The lightweight ORM

    The TypeScript course devotes two separate chapters to accessing databases via a ORM ([Object-Relational Mapping]): [TypeORM], followed by [Prisma], using the same example schema. Both are based on a common principle: describe the schema once (using TypeORM decorators on classes, or a [.prisma] file for Prisma), then letting the tool generate, at startup or during compilation, all the code that translates object reads/writes into SQL—including the loading of relationships between tables.

    Dart does not have a mature and widely adopted equivalent to these two tools for MySQL: there are Dart ORM libraries, but they are primarily designed for Flutter/SQLite ([Drift], [Floor]) or for different architectures - Prisma itself does not offer a Dart client. Rather than forcing an artificial mapping such as “such-and-such Dart package = TypeORM” or “such-and-such package = Prisma,” this chapter takes a different approach, one that is more educationally sound: showing what a ORM actually does by writing it yourself in a deliberately minimal version—hence the name [ORM léger].

    // repository.dart
// A hand-written “lightweight ORM”: a very generic [Repository] class
// inspired by the TypeORM Repository (`AppDataSource.getRepository(...)`,
// `.find()`, `.findOneBy()`, `.save()`, `.delete()`), but built on
// a simple table, without decorators or automatic loading of
// relationships—see README.md for a full discussion of this choice.
//
// [migration] This file originally used [package:mysql1]; it was
// ported to [package:mysql_client_plus] (see comment by
// pubspec.yaml). The most noticeable change for the caller is the
// style of parameterized queries: mysql1 used placeholders
// POSITIONNELS ("?" followed by a list of values in order), whereas
// [mysql_client_plus] uses placeholders NOMMÉS (":column" + a
// [Map] column name -> value)—which works out rather well here
// since this repository already works with [Map<String, Object?>] de
// columns.
import 'package:mysql_client_plus/mysql_client_plus.dart';

// [T]: the type of the entity managed by this repository (Person, Class...)
class Repository<T> {
  final MySQLConnection connexion;
  // table name SQL
  final String table;
  // primary key column name
  final String colonneCle;
  // constructs a [T] entity from a SQL result row
  final T Function(ResultSetRow ligne) depuisLigne;
  // returns the columns SQL (column name -> value) of an entity [T],
  // primary key COMPRISE (useful for both insertion and
  // updates)
  final Map<String, Object?> Function(T entite) versColonnes;
  // retrieves the value of the primary key of an entity [T]
  final Object? Function(T entite) cle;

  Repository(
    this.connexion, {
    required this.table,
    required this.colonneCle,
    required this.depuisLigne,
    required this.versColonnes,
    required this.cle,
  });

  // equivalent to `repo.find({ order: { column: 'ASC' } })`
  Future<List<T>> findAll({String? orderBy}) async {
    final sql = 'select * from $table${orderBy != null ? ' order by $orderBy' : ''}';
    final resultats = await connexion.execute(sql);
    return resultats.rows.map(depuisLigne).toList();
  }

  // equivalent to `repo.findOneBy({ column: value })` - [conditions] is
  // an equality "ET" on each provided column; the keys of [conditions]
  // serve as both the column name SQL and the placeholder name
  // NOMMÉ (":column")—they are therefore reused as-is as
  // query parameters
  Future<T?> findOneBy(Map<String, Object?> conditions) async {
    final ou = conditions.keys.map((c) => '$c = :$c').join(' and ');
    final resultats = await connexion.execute(
      'select * from $table where $ou limit 1',
      conditions,
    );
    if (resultats.rows.isEmpty) return null;
    return depuisLigne(resultats.rows.first);
  }

  // equivalent to `repo.findOneByOrFail(...)` / `findOneOrFail(...)`
  Future<T> findOneByOrFail(Map<String, Object?> conditions) async {
    final trouve = await findOneBy(conditions);
    if (trouve == null) {
      throw StateError('Aucune ligne trouvée dans [$table] pour $conditions');
    }
    return trouve;
  }

  // equivalent to `repo.save(entity)`: insert if the key does not exist
  // again, update otherwise—exactly the "upsert" behavior of
  // `save()` on the TypeORM side
  Future<void> save(T entite) async {
    final colonnes = versColonnes(entite);
    final cleCourante = cle(entite);
    final existeDeja = await findOneBy({colonneCle: cleCourante}) != null;
    if (existeDeja) {
      final aMettreAJour = colonnes.keys.where((c) => c != colonneCle);
      final assignations = aMettreAJour.map((c) => '$c = :$c').join(', ');
      // the columns to update, PLUS the key (under the same name as
      // placeholder as in the WHERE clause) — no collision possible
      // since [colonneCle] has just been excluded from [aMettreAJour]
      final valeurs = <String, Object?>{
        for (final c in aMettreAJour) c: colonnes[c],
        colonneCle: cleCourante,
      };
      await connexion.execute('update $table set $assignations where $colonneCle = :$colonneCle', valeurs);
    } else {
      final noms = colonnes.keys.join(',');
      final placeholders = colonnes.keys.map((c) => ':$c').join(',');
      await connexion.execute('insert into $table ($noms) values ($placeholders)', colonnes);
    }
  }

  // equivalent to `repo.delete({ column: value })`
  Future<void> delete(Map<String, Object?> conditions) async {
    final ou = conditions.keys.map((c) => '$c = :$c').join(' and ');
    await connexion.execute('delete from $table where $ou', conditions);
  }
}

    // orm_03_joined_queries.dart
// Contains databases/typeorm/typeorm-03-joined-queries.ts.
//
// Highlights the queries SQL that need to be written to retrieve
// information spread across multiple tables—which TypeORM
// does for you behind the `relations` option, via a JOINTURE SQL
// (`JOIN`). Unlike orm_02_ecole.dart (which simulated a load
// of a relationship with DEUX separate requests, to keep things simple), this file
// writes the VRAIES joins SQL—exactly what TypeORM does
// behind the scenes, but made fully visible.
//
// [différence de fond avec TypeScript] TypeORM (such as SQLAlchemy, used
// by the original Python course) does not perform lazy loading by default
// for “standard” entities: you must explicitly request the
// relations to load, using the `relations` option. Our “lightweight” ORM
// takes this principle even further, since there is no NI lazy
// "magic" relation loading: each join is
// SQL handwritten, line by line—the price to pay for not depending
// on any object-relational mapping library.
//
// [migration mysql_client_plus] as in repository.dart, the
// positional placeholders ("?") from MySQL 1 become placeholders
// NOMMÉS (":id", ":name"...), and access to the columns of a row in
// result set ([ligne.fields['x']] with mysql1) becomes a typed call
// ([ligne.typedColByName<T>('x')]).
import 'package:mysql_client_plus/mysql_client_plus.dart';
import 'entities.dart';

// reads a column SQL DECIMAL/NUMERIC (here [notes.valeur] and
// [matieres.coefficient]) as a [num]. [package:mysql_client_plus] knows
// convert a DECIMAL to [String] (any SQL file can be read
// as [String]), but not directly from PAS to [num] or [double] -
// `typedColByName<num>(...)` then raises "Cannot convert MySQL type 246 to
// requested type num" (246 = NEWDECIMAL, the internal type MySQL of the
// DECIMAL columns). We therefore read the column as [String], then
// convert it ourselves.
num _decimal(ResultSetRow ligne, String colonne) => num.parse(ligne.typedColByName<String>(colonne)!);

// students by ID, with their class (JOIN students/classes)
Future<Eleve> _eleveAvecClasse(MySQLConnection cnx, int id) async {
  final resultats = await cnx.execute(
    'select e.id as e_id, e.nom as e_nom, e.prenom as e_prenom, e.classe_id as e_classe_id, '
    'c.id as c_id, c.nom as c_nom '
    'from eleves e join classes c on e.classe_id = c.id where e.id = :id',
    {'id': id},
  );
  final ligne = resultats.rows.first;
  return Eleve(
    id: ligne.typedColByName<int>('e_id')!,
    nom: ligne.typedColByName<String>('e_nom')!,
    prenom: ligne.typedColByName<String>('e_prenom')!,
    classeId: ligne.typedColByName<int>('e_classe_id')!,
    classe: Classe(id: ligne.typedColByName<int>('c_id')!, nom: ligne.typedColByName<String>('c_nom')!),
  );
}

// class by ID, with the list of its students (JOIN classes/students)
Future<Classe> _classeAvecEleves(MySQLConnection cnx, int id) async {
  final resultats = await cnx.execute(
    'select c.id as c_id, c.nom as c_nom, e.id as e_id, e.nom as e_nom, e.prenom as e_prenom '
    'from classes c left join eleves e on e.classe_id = c.id where c.id = :id',
    {'id': id},
  );
  final premiereLigne = resultats.rows.first;
  final classe = Classe(id: premiereLigne.typedColByName<int>('c_id')!, nom: premiereLigne.typedColByName<String>('c_nom')!);
  classe.eleves = [
    for (final ligne in resultats.rows)
      Eleve(
        id: ligne.typedColByName<int>('e_id')!,
        nom: ligne.typedColByName<String>('e_nom')!,
        prenom: ligne.typedColByName<String>('e_prenom')!,
        classeId: classe.id,
      ),
  ];
  return classe;
}

// Database: databases/typeorm/typeorm-04-stats.ts.
//
// Calculates, for a given student, their grade point average weighted by the coefficients
// subjects, as well as the minimum and maximum grades.
//
// [différence avec TypeScript] typeorm-04-stats.ts warned that the
// `decimal` columns in MySQL (here, note.valeur and matiere.coefficient)
// are returned by the mysql2 driver as CHAÎNES DE
// CARACTÈRES at runtime (to avoid losing precision), despite their
// declared type `number`—a classic pitfall of TypeScript, where the
// static type may not reflect the actual value at runtime. On the Dart side,
// [package:mysql_client_plus] has a similar pitfall, but it is handled by the
// compiler rather than hidden at runtime: the typed access
// (`typedColByName<T>(...)`) cannot convert a column DECIMAL
// (internal type SQL 246, "NEWDECIMAL")—neither to [num] nor to [double]—it
// raises `MySQLProtocolException: Cannot convert MySQL type 246 to requested
// type num`. The only guaranteed conversion for N'IMPORTE QUEL type SQL is
// [String]; therefore, the columns DECIMAL are read as [String] with
// `typedColByName<String>(...)`, and then we convert them ourselves using
// [num.parse]—see [_decimal] below.
import 'package:mysql_client_plus/mysql_client_plus.dart';

// reads a column SQL DECIMAL/NUMERIC as a [num] (see comment on
// file header)
num _decimal(ResultSetRow ligne, String colonne) => num.parse(ligne.typedColByName<String>(colonne)!);

// calculates the statistics (weighted average, minimum, maximum) for a student
Future<void> _statsEleve(MySQLConnection cnx, int idEleve) async {
  final eleveLigne = (await cnx.execute('select id, nom, prenom from eleves where id = :id', {'id': idEleve})).rows.first;
  print(
    'Student statistics {"id":${eleveLigne.typedColByName<int>('id')},"last_name":"${eleveLigne.typedColByName<String>('last_name')}",""first_name":"${eleveLigne.typedColByName<String>('first_name')}"}',
  );

  final notes = await cnx.execute(
    'select n.valeur as value, m.nom as matiere_nom, m.coefficient as coefficient '
    'from notes n join matieres m on n.matiere_id = m.id where n.eleve_id = :id',
    {'id': idEleve},
  );

  if (notes.rows.isEmpty) {
    print('  aucune note.');
    return;
  }

  num sommePonderee = 0;
  num sommeCoefficients = 0;
  num mini = double.infinity;
  num maxi = double.negativeInfinity;

  for (final ligne in notes.rows) {
    // explicit conversion via [_decimal] (see note at the top of the file):
    // [valeur] and [coefficient] are therefore valid [num] values, not strings
    final valeur = _decimal(ligne, 'valeur');
    final coefficient = _decimal(ligne, 'coefficient');
    sommePonderee += valeur * coefficient;
    sommeCoefficients += coefficient;
    if (valeur < mini) mini = valeur;
    if (valeur > maxi) maxi = valeur;
    print(
      ' note=${valeur.toStringAsFixed(2)} subject="${ligne.typedColByName<String>('matiere_nom')}" '
      '(weighting factor ${coefficient.toStringAsFixed(2)})',
    );
  }

  final moyenne = sommePonderee / sommeCoefficients;
  print('  moyenne pondérée=${moyenne.toStringAsFixed(2)}, mini=${mini.toStringAsFixed(2)}, maxi=${maxi.toStringAsFixed(2)}');
}

    7.2.7. What the lightweight ORM does not do

    Unlike TypeORM/Prisma: no schema generation ([synchronize]/migrations), no decorators, no lazy loading or identity cache, no query builder ([QueryBuilder]), and loading a relationship is TOUJOURS a second query or a hand-written join—never automatic. This is a deliberate compromise: enough to illustrate the repository pattern using the example from the course, without claiming to replace a real repository in production.
